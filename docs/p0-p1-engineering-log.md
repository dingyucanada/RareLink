# RareLink P0/P1 工程实施与限制日志

> 文档状态：持续更新
>
> 适用范围：真实三物理站点联邦学习工程化
>
> 原则：区分“代码已实现”“隔离环境已验收”“真实设备已验证”“医院生产已批准”。

## 1. 完成判定

RareLink 不以存在接口、按钮或测试桩作为生产完成证据。每项能力分别记录四级状态：

| 等级 | 定义 |
| --- | --- |
| L1 代码实现 | 已有失败关闭的实现及自动测试 |
| L2 隔离集成 | 三个独立进程或容器完成协议验收，没有使用真实患者数据 |
| L3 物理联邦 | 三台独立 DGX Spark、正式 NVIDIA FLARE Kit、独立证书和网络完成端到端演练 |
| L4 医院生产 | 完成医院身份、密钥、伦理、数据授权、安全评估、运维和临床科研治理 |

当前自动验收只能够证明 L1/L2。L3/L4 不能由单机进程、Fake CLI、SimEnv、合成数据或文档声明替代。

## 2. 逐项状态矩阵

状态含义：**已实现**表示 L1 自动测试通过；**隔离验收**表示同时具备 L2
多进程/本地集成证据；**部分实现**表示软件边界已完成但现场能力仍有硬依赖；
**外部阻塞**表示不能由代码仓库合法产生完成证据。

## 4. 禁止使用的替代证据

以下结果可以用于开发，但不能关闭对应的生产验收项：

- 单台 Spark 上运行三个逻辑站点；
- NVIDIA FLARE SimEnv 或 Fake CLI；
- 合成 MRI、公开基准的单次实验或赛事 Demo；
- 自签名临时证书代替医院 CA、CRL 和轮换；
- Demo Token 代替医院 OIDC；
- SQLite 代替生产 PostgreSQL；
- TLS/mTLS 代替安全聚合；
- 哈希链代替 WORM 存储；
- 生成了一份攻击脚本即声称模型通过隐私安全评测。

  `2/3`、迟到轮次、Job/合同/代码/数据错配均不能生成包。
- 隐私门强制检查三站 epsilon 不超过批准上限；安全门强制 Agent 红队、ART

- 使用两条 Ed25519 链分别保护模型发布与完整证据包。包内携带不依赖 RareLink
  应用的离线验证器，验证器自身也进入签名 Manifest。
- 审计边界保持准确：离线端核验完整性、previous/head 链接、协调端已验证声明和
  包签名，但不会导出 HMAC 密钥，因此不声称离线重新计算了协调端 HMAC。
- 代码、数据与模型本体不进入包；离线端验证摘要格式、跨文件一致性和签名。重新
  计算本体摘要必须在各自受控环境完成，不能为了“可验证”导出患者数据或私有模型。
- 当前交付的是生成器、双层验签器、严格 schema、内嵌离线工具和负向测试；由于
  尚无三台真实 Spark 的同一正式 Job、两位真实治理主体审批和授权医学隐私评测，
  仓库不会预生成一份冒充 L3/L4 的“已通过”正式证据包。现场资产齐备后由协调端
  组装 reviewed source，再使用受控私钥生成发布物。
