# ADR-0002：站点身份、证书与院内数据边界

- **状态：** Accepted
- **日期：** 2026-07-26
- **决策人：** RareLink 工程、安全、隐私与医学负责人
- **影响范围：** Provisioning、Site Agent、数据服务、日志、Agent、工件和网络

## 背景

RareLink 的核心承诺是原始 MRI、标签和病例级证据留在所属医院。仅使用 TLS 或把路径写在本地配置中不足以保证这一点：站点可能拿错 Client Kit，日志可能意外记录路径，manifest 可能混入外院病例，中心或 Agent 也可能通过扩展接口越权访问。

因此，站点身份、证书身份、数据归属和运行合同必须被密码学地或确定性地绑定，并通过字段白名单和自动测试落实，而不能只依赖部署说明。

## 决策

1. 每家医院使用唯一、稳定、非患者相关的 `site_id`，由中心拓扑合同管理。
2. NVIDIA FLARE Provisioning 为每站生成独立 Client Kit；证书 SAN/Subject 必须与 `site_id` 绑定。
3. Site Agent 注册时同时验证：
   - mTLS 证书链、有效期和吊销状态；
   - 证书身份与请求 `site_id`；
   - 签名 nonce，防止注册重放；
   - agent/code/policy 版本与合同兼容性。
4. Client Kit 和私钥只存在所属医院节点；Admin Kit 只存在协调方受控环境。
5. 首个正式数据路径只支持本地 NIfTI + JSON manifest。manifest 每条记录必须属于当前 `site_id`。
6. 中心只接收规范化 `dataset_fingerprint`、记录数量、质控结论和签名；不接收 manifest 原文。
7. 下列信息禁止从医院出站：
   - DICOM/NIfTI/标签或其可逆派生物；
   - 患者姓名、ID、UID、检查号、日期等直接或间接标识；
   - 文件名、本地绝对路径、病例级指标和病例级错误；
   - 本地 checkpoint、原始 batch 日志和未批准小分组统计。
8. Control API、Agent Gateway、监控和公共演示不得挂载医院影像盘。
9. Agent 仅能读取锁定合同和通过发布策略的聚合证据；无 Site Agent、FLARE、存储或密钥工具权限。
10. 数据版本变化产生新指纹；依赖旧指纹且尚未执行的合同自动失效，运行中是否中止由预先锁定策略决定。

## 数据指纹

数据指纹必须基于规范化、无路径的记录摘要生成，例如：站点、模态完整性、几何/标签质控结果、确定性划分标记以及每个本地对象的不可逆内容摘要。中心只能看到最终集合摘要和计数。

指纹不是匿名化机制，也不能公开用于枚举小规模数据集。其访问受 RBAC 和研究合同控制。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 共享对象存储集中训练 | 运维简单 | 违反目标数据边界，扩大泄露影响 | 拒绝 |
| 中心保存 manifest 原文 | 易审计 | 泄露路径/病例结构，中心越权 | 拒绝 |
| 每站独立 kit + 本地 manifest + 脱敏收据 | 边界清晰、可核验 | Provisioning 和现场管理成本增加 | 采用 |
| Agent 直接读取训练日志 | 报告丰富 | 容易泄露病例级和路径信息 | 拒绝 |

## 后果

- 站点部署和证书分发必须由医院与协调方共同完成；
- 站点不可互换 Client Kit，拓扑变化需要重新 Provision；
- 故障诊断以本地日志为主，中心只看到脱敏错误码；
- 数据质控与 manifest 工具成为正式安全边界，需要与训练代码同等测试；
- PACS/DICOM 接入必须另做数据保护设计，不能直接扩展当前上传接口。

## 强制验证

- 使用医院 B 的 kit 注册医院 A 必须失败；
- manifest 包含外站记录、患者字段或越界路径时必须在读取影像前失败；
- 自动扫描 API payload、日志、metrics、trace 和证据包中的敏感字段；
- 网络捕获证明正式协议未传输 R4 数据；
- 私钥、kit、manifest、本地路径和患者数据必须被 `.gitignore`、秘密扫描和发布检查阻断；
- 撤销证书后，站点不能注册或领取新命令。

## 何时重新评审

- 增加 DICOM/PACS、FHIR 像素或跨境数据流；
- 使用安全执行环境、安全聚合或新的信任模型；
- 需要让第三方模型、云服务或外部 Agent 处理 R2/R3/R4 数据。
