# ADR-0003：任务幂等、固定参与方与 Quorum

- **状态：** Accepted
- **日期：** 2026-07-26
- **决策人：** RareLink 工程、统计与安全负责人
- **影响范围：** Control API、Federation Controller、Site Agent、FLARE 作业、审计与结果发布

## 背景

联邦训练横跨 HTTP、控制数据库、NVIDIA FLARE、医院网络和本地训练进程。任何一层都可能超时、重试或重启。如果没有端到端幂等，同一作业或同一轮可能被执行两次；如果只按“已收到的站点数”动态聚合，三站研究可能在某站掉线时静默变成两站研究，破坏预注册合同和统计解释。

系统需要把网络的“至少一次投递”收敛成业务的“每个有效动作恰好产生一次结果”，并把 quorum 作为不可绕过的研究合同，而非运维便利开关。

## 决策

### 幂等层级

1. API 写请求必须带 `Idempotency-Key`，服务端保存操作者、作用域、规范化请求哈希和原响应。
2. 作业提交使用稳定 `submission_token`，关联 RareLink Job ID、作业包哈希和合同哈希。
3. 每个站点命令具有不可变 `command_id` 和单调 `attempt`。
4. 每个训练更新唯一绑定：

   `job_id + job_attempt + round_id + site_id + base_model_hash`

5. 重复请求：
   - 请求体相同：返回原结果；
   - 相同 key 但请求体不同：返回 `409 Conflict` 并记录安全审计；
   - 已完成 command/round：返回已签名收据，不重新运行。
6. 所有幂等记录必须是持久化数据，并具有至少覆盖作业保留期的生命周期。
7. 外部提交超时不能立即判定失败，必须进入 `SUBMIT_UNKNOWN` 并对账。

### Quorum 与参与方

1. `expected_sites`、`required_quorum`、超时和掉站策略在合同锁定后不可变。
2. 三站正式试点默认要求 3/3；只有三站有效更新均被接受才可聚合。
3. 2/3 不得被标记为成功，也不得静默降低 quorum。
4. 降低 quorum 或移除站点必须创建合同新版本、重新评估统计/隐私影响并双人审批，只影响新作业。
5. 迟到更新、重复更新、错误轮次、错误 base model、签名错误或非预期站点更新必须拒绝。
6. 掉站时进入 `DEGRADED`，由合同决定等待、恢复或 abort。
7. 所有接受/拒绝决定进入审计链，并在运行卡中报告。

## 一致性与事务

- Control API 使用 PostgreSQL 事务和唯一约束实现幂等，不依赖进程内锁；
- 站点本地使用 durable store 和唯一约束，进程重启后仍能识别重复命令；
- 状态修改使用资源版本/乐观锁，冲突返回 409/412；
- Outbox/Inbox 模式保证数据库状态与异步事件最终一致；
- Site Agent 和 Controller 定期对账，数据库不以心跳缺失直接推断训练已停止；
- 只有外部 FLARE 状态、站点收据、轮次更新和模型核验一致时才进入 `SUCCEEDED`。

## 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 前端禁用按钮防重 | 简单 | 刷新、并发、重试和多用户时失效 | 拒绝 |
| 进程内全局锁 | 单机有效 | 重启/多实例失效，无法覆盖外部提交 | 拒绝 |
| 持久幂等键 + 唯一约束 + 对账 | 可恢复、可审计 | 需要更多状态和存储 | 采用 |
| 动态 best-effort quorum | 作业更容易完成 | 改变研究设计和风险模型 | 拒绝 |
| 合同固定 quorum | 结论可解释、可审计 | 掉站时作业可能中止 | 采用 |

## 必测场景

1. 十个并发相同提交请求只产生一个外部 Job；
2. 相同幂等键和不同请求体返回冲突；
3. 外部提交成功但 HTTP 响应丢失，重试能找回原 Job；
4. Site Agent 重启后收到相同 start，不重复创建训练进程；
5. 同一更新发送两次，只接受一次；
6. Round 1 更新在 Round 2 到达时被拒绝；
7. 使用错误 base model 的更新被拒绝；
8. 只收到 2/3 更新时不聚合；
9. 站点恢复后只补齐缺失更新；
10. 运行中修改 quorum 被拒绝；
11. abort 响应丢失时保持未知状态并对账；
12. Controller 数据库恢复后能够重建外部 Job 和站点命令映射。

## 后果

- 状态模型包含 `SUBMIT_UNKNOWN`、`ABORT_UNKNOWN`、`DEGRADED` 等中间状态，UI 必须准确展示；
- 某些作业会因站点掉线而无法完成，这是保护研究合同的预期行为；
- 数据库 schema、消息和 FLARE Adapter 必须携带稳定标识与版本；
- 运维人员不能通过数据库直接改成成功或降低 quorum；
- 重试是原 Job 的新 attempt，不是掩盖失败的新实验。

## 何时重新评审

- 研究协议明确允许最低参与方而非固定全体站点；
- 引入异步联邦、容错安全聚合或动态站点抽样；
- NVIDIA FLARE 提供原生的端到端幂等与可验证 quorum 协议。
